# SemCache Telecom — Application Design & Engineering Standards

This document defines the visual design system, component architecture, conversational UX patterns, and frontend engineering standards for the **SemCache** telecommunications customer support platform.

---

## 1. Product Vision & Domain Positioning

SemCache is an AI-powered customer support platform for a telecommunications provider. Customers interact with **Telecom Assistant**, an intelligent support assistant that answers questions across core telecom domains:

- **Mobile Plans & Subscriptions** — comparing 5G unlimited, family, and prepaid plans.
- **Mobile Internet & Data Usage** — checking remaining high-speed data and billing cycle resets.
- **Account Balance & Payments** — AutoPay setup, card payments, and billing inquiries.
- **Roaming & International Services** — travel passes, EU/global zones, and daily rates.
- **SIM Cards & eSIM Activation** — QR activation and device transfer instructions.
- **Network Connectivity & Troubleshooting** — APN settings, coverage checks, and signal fixes.
- **Account Management & Human Support** — profile updates and seamless escalation to a human specialist.

### Design Principle: Transparency of Internal Infrastructure

> **The customer must feel like they are chatting with the official AI support assistant of their telecommunications provider.**

While SemCache uses Semantic Caching, `pgvector` similarity search, adaptive thresholds, and OpenRouter LLMs internally, **none of those implementation details may ever be exposed in customer-facing UI**:

- **Prohibited in customer UI**: similarity scores, adaptive thresholds, cache hit/miss badges, embedding metrics, token counts, latency timings, or internal LLM model identifiers.
- Responses must feel natural, consistent, and domain-authentic regardless of whether they are served from Semantic Cache or generated by the LLM.

## 2. Visual Identity & Design System Tokens

The design system is defined in [apps/frontend/src/index.css](../apps/frontend/src/index.css) using **Tailwind CSS v4** `@theme inline` tokens and OKLCH color variables.

### 2.1 Color Palette

- **Default Theme**: **Light Mode** (`useUiStore` defaults to `'light'`). Dark Mode is supported via `.dark` class toggling.
- **Primary Brand Color**: Deep Telecom Blue / Indigo (`--primary`: `oklch(0.42 0.17 262)` in light mode, `oklch(0.62 0.18 258)` in dark mode).
- **Secondary Accent**: Cyan / Teal (`--accent`: `oklch(0.94 0.03 205)`, `--accent-foreground`: `oklch(0.32 0.09 215)`).
- **Surfaces**:
  - Neutral canvas background (`--background`: `oklch(0.985 0.004 240)`).
  - Pure white elevated cards and message surfaces (`--card`: `oklch(1 0 0)`).
  - Subtle blue-tinted secondary panels for conversation history (`--secondary`: `oklch(0.95 0.015 245)`).
- **Borders**: Subtle neutral borders (`--border`: `oklch(0.91 0.01 245)`).
- **Visual Restraint**: Avoid excessive gradients, heavy glassmorphism, or gratuitous animations. Prioritize legibility, contrast, and calm hierarchy.

### 2.2 Typography & Radii

- **Font Family**: `Inter` (`'Inter', -apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, sans-serif`) loaded via [apps/frontend/index.html](../apps/frontend/index.html).
- **Border Radius Scale** (`--radius: 0.75rem` / `12px`, within the `10–14px` target range):
  - `--radius-sm`: `8px` (`calc(var(--radius) - 4px)`)
  - `--radius-md`: `10px` (`calc(var(--radius) - 2px)`)
  - `--radius-lg`: `12px` (`var(--radius)`)
  - `--radius-xl`: `14px` (`calc(var(--radius) + 2px)`)

## 3. Frontend Architecture & UI Component Standards

`@semcache/frontend` follows a **Feature-Sliced Design (FSD)** directory layout:

```text
apps/frontend/src/
├── app/        # Router, RootLayout, QueryClient & Auth bootstrap
├── pages/      # Route-level pages (home, sign-in, sign-up, forgot-password)
├── widgets/    # Composite layout shells (AuthShell)
├── features/   # Domain features (chat, auth, theme) with api/, model/, ui/
└── shared/     # Reusable UI primitives (shadcn/ui + Radix UI), API client, helpers
```

### 3.1 `shadcn/ui`, Radix UI & Tailwind CSS v4

- All interactive primitives are built on **Radix UI** (`@radix-ui/react-dialog`, `@radix-ui/react-dropdown-menu`, `@radix-ui/react-avatar`, `@radix-ui/react-tooltip`, `@radix-ui/react-separator`, `@radix-ui/react-label`, `@radix-ui/react-slot`) styled with Tailwind CSS utility classes and `class-variance-authority` (`cva`).
- Reusable primitives live in `apps/frontend/src/shared/ui/`:
  - `Button`, `Input`, `Textarea`, `Label`, `Badge`, `Card` (+ subcomponents)
  - `Avatar`, `Separator`, `Tooltip`, `DropdownMenu`, `Dialog` / `SheetContent`
  - `BrandLogo` and `MarkdownContent`
- Variant definitions (`button-variants.ts`, `badge-variants.ts`) are kept in dedicated `.ts` files to satisfy `react/only-export-components` linting without warnings.

### 3.2 Accessibility Standards

- Semantic landmarks (`<header>`, `<main>`, `<aside>`, `<footer>`).
- Visible keyboard focus rings (`focus-visible:ring-ring/50 focus-visible:ring-[3px]`).
- Accessible names (`aria-label`, `aria-pressed`, `aria-current`, `aria-invalid`, `role="alert"`, `role="status"`).
- Keyboard-first composer: `Enter` sends, `Shift + Enter` inserts a newline.

## 4. Conversational UX Patterns

### 4.1 Chat Header (`ChatHeader`)

- Mobile drawer button (`< md`) and desktop sidebar collapse toggle (`>= md`).
- **SemCache** `BrandLogo` + **Telecom Assistant** identity, pulsing online availability badge, and `"Your personal support assistant"` subtitle.
- Unobtrusive **"Talk to a human agent"** trigger opening `HumanEscalationDialog` (displays estimated wait time, context handoff summary, and transfer confirmation).
- Customer profile/avatar `DropdownMenu` with account settings (`ProfileSettingsDialog`), operator directory (`AdminOperatorDialog` for `UserRole.ADMIN`), and sign-out action.

### 4.2 Welcome State & Suggested Questions (`ChatWelcomeState`)

When starting a new session or empty conversation, customers see:

- Greeting: _"Hello! Welcome to SemCache Support. I'm your AI assistant, here to help with your mobile services. What can I help you with today?"_
- Six interactive telecom suggestion cards (`TELECOM_SUGGESTIONS`):
  1. **Mobile Plans** — _"Which mobile plan is right for me?"_
  2. **Internet Usage** — _"How much mobile data do I have left?"_
  3. **Payments** — _"How can I pay my bill?"_
  4. **Roaming** — _"How does international roaming work?"_
  5. **SIM & eSIM** — _"How do I activate my eSIM?"_
  6. **Technical Support** — _"My mobile internet isn't working."_

### 4.3 Message Rendering, Branching & Feedback (`ChatMessageItem`)

- **Customer messages**: right-aligned, primary blue surface, timestamp (`HH:mm`), inline **Edit message** action creating a new sibling branch in the conversation graph, and branch switcher toggle (`< 1 / N >`) when multiple versions exist at that node.
- **Assistant messages**: left-aligned, white card surface, timestamp, structured Markdown rendering (`MarkdownContent` supporting headings, lists, blockquotes/callouts, code/instruction blocks, inline formatting, and links).
- **Feedback controls**: Thumbs up (`Helpful response`), Thumbs down (`Not helpful response`), and Copy (`Copy response`).
- **Typing indicator**: animated three-dot indicator with `"Telecom Assistant is typing..."` while awaiting response.

### 4.4 Conversation History & Responsive Layout (`ConversationSidebarContent` / `MobileConversationDrawer`)

- **Desktop**: collapsible secondary sidebar (`280px–320px`) displaying `"New conversation"`, optional conversation search, conversation title, 3-dots context menu (`Rename` and `Delete` opening dedicated modal dialog windows for title editing and deletion confirmation), last message preview, relative timestamp (`date-fns`), and active indicator bar.
- **Mobile & Tablet**: single-column chat layout with compact header and slide-over `SheetContent` drawer for conversation history.

## 5. Authentication & Operator Surfaces

- **Customer Auth Pages** (`/sign-in`, `/sign-up`, `/forgot-password`): unified under `AuthShell` with SemCache Telecom branding, Zod + React Hook Form validation, and HttpOnly session cookie security.
- **Profile & Operator Dialogs**:
  - `ProfileSettingsDialog` integrates with `PATCH /users/:id`.
  - `AdminOperatorDialog` integrates with `GET /admin/users` and `DELETE /admin/users/:id/sessions` for `ADMIN` operators.
- No backend authentication or dialog API contracts are altered.

## 6. Engineering Quality & Verification Standards

All changes in the monorepo must satisfy:

1. **Strict TypeScript**: `strict: true`, `noImplicitAny: true`, `strictNullChecks: true` (`pnpm typecheck`).
2. **Static Analysis**: Oxlint across all apps and packages (`pnpm lint`).
3. **Formatting**: Prettier (`pnpm format:check`).
4. **Duplication Guard**: `jscpd` (`pnpm jscpd`) with zero copy-paste duplication above configured thresholds.
5. **Automated Testing**:
   - Frontend unit & component tests with Vitest + React Testing Library (`pnpm --filter @semcache/frontend test`).
   - Full monorepo build & test suite (`pnpm build && pnpm test`).
   - End-to-end Playwright smoke suite (`apps/frontend/e2e/smoke.spec.ts`).
